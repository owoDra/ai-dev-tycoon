# Phase 21: 会社の成長と複数チーム

## 目的
遊ぶほど会社が成長し、人員と請け負える案件の規模が大きくなる。成長すると複数のチームを持ち、チームごとに **人間の PM か AI の PM** に運営を任せられるようになる。

**序盤は管理者を雇えない。** 小規模なチームでは、誰がどの Task をどのモードで担当するかまで、プレイヤーがすべて決める（今の遊び方）。成長して管理者を置けるようになってから、委任の判断が加わる。

## 前提
Phase 20

## やること
1. **会社の規模（`content/companyTiers.ts`）**
   - 段階の例：個人事業 → スタートアップ → 小規模 → 中堅 → 大手
   - 昇格の条件は、累計の利益・評判・納品数で決める。段階ごとに、人員の上限・受けられる案件の規模・引き合いの数・チーム数の上限・オフィスの固定費が変わる
   - 昇格は Tier 4 の演出と、新しく解放された要素の案内で見せる
2. **チーム（`core/teams.ts`）**
   - 社員と AI Worker をチームに所属させ、チームに案件を割り当てる。AI Worker も複数持てるようにする（Seat と運用者の関係は今のまま）
   - プレイヤーが直接操作する **直轄チーム** は常に1つ。チームが1つだけの間は、今と同じく全員の担当をプレイヤーが決める
3. **管理者と委任（`core/manager.ts`）**
   - 管理者を置けるのは、規模が一定以上になってから
   - 直轄以外のチームには管理者を置き、管理者が担当モードと担当者を自動で決める（決定論的なロジック。Command を発行する形にして、プレイヤーの操作と同じ経路で state を変える）
   - **人間 PM**：社員を1人 PM に任命する。PM の稼働は人日として数える（利益 / 人日 を下げる）。判断は堅実で、Task の性質に合ったモードを選ぶ
   - **AI PM**：Seat の使用量と AI 費用がかかるが、人日は使わない。判断にばらつきがあり、品質要求の高い案件では見逃し・事故が増える
   - 委任したチームの状況は、チームのカード（進捗・利益 / 人日・問題）で見る。介入して直轄に戻すこともできる
4. **画面**：チームの一覧と編成の画面。3D ワールドではチームごとに島をまとめて表示する

## テスト
