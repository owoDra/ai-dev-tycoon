# Phase 27: 実務モードの計算の根拠を見せる

## 目的
実務モードの試算について、「なぜこの数字になるのか」をプレイヤーが追えるようにする。社内で説明に使える根拠つきの報告を出せるようにする。

## 前提
Phase 26

## 現状（2026-10-28 調査）
計算はゲーム本編と同じ式（`core/practice.ts` → `core/expectation.ts`・`core/formulas.ts`）だが、画面には結果しか出ていない。
- 工程ごとの「改善後 M分」の内訳（指示・レビュー・手戻り）が出ていない。AI だけの担当で人間の時間がほぼ0になる理由が見えない
- 「AI 適性」が隠れた4つの値（適性・難しさ・品質の要求・失敗のリスク）を決めているのに、成功率と見逃しの確率（`pEscape`）が出ていない
- 前提（自分の速さ = 1、1人日 = 480分、年の回数 240 / 52 / 12、お願いの遵守率 50%）が出ていない
- ROI・人日あたりの利益・品質の式が出ていない。年間の削減額も出ていない
- Harness の見込みの見出しが、ゲームの文言（「この案件の AI の仕事」）のまま

## やること
1. **工程の内訳バー**：人間の時間を「指示・自分の作業・レビュー・手戻りの見込み」、AI の時間を「作業・検証・修正」に分けて出す。値は `core/practice.ts` が内訳つきで返す（式を UI に重複させない）
2. **「なぜこの数字？」**：開くと、実際の値を入れた式を出す（例：「人間の時間 = 指示（20分 × 5% = 1分）+ レビュー（…）」）。式の文言は `i18n/ja.ts`
3. **前提のカード**：自分の速さ・1人日・年の回数・お願いの遵守率・モデルの性能と単価。年の回数と人件費はその場で変えられる
4. **AI 適性の見える化**：選んだ適性で、成功率と見逃しの確率を出す
5. **品質とのつながり**：「レビューなし → 見逃し 12% → 品質 88%」のように、時間を減らした代償を工程ごとに出す
6. **結果の項目**：年間の削減額、ROI の式（削減額 − AI の追加コスト）÷ AI の追加コスト を出す
7. **報告のコピー**：前提・内訳・式を報告に含める
8. 実務モードでの Harness の見込みの見出しを、実務向けの文言にする

## テスト

- `tests/unit/practice-report.test.ts`：コピーする報告に前提と式が含まれること
