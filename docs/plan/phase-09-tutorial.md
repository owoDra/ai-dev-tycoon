# Phase 09: 機能解放システム・最初の3分

## 目的
企画書50〜51章。長い説明画面は作らず、最初の案件そのものをチュートリアルにする。起動から3分以内に「Humanだけ → AI導入 → 作業時間が激減 → AIのミス → Harnessで改善 → さらに改善」までを体験させる。

## 前提
D4（演出と音の手触りが決まっていることで、気持ちよさまで含めた体験として検証できる）。この Phase の後に D5 で通しプレイを行い、テンポと文言を調整する。

## やること
1. **機能解放システム（`content/unlocks.ts` と `core/unlocks.ts`）**
   - `UnlockDef`：id、対象機能（担当モード・パネルのセクション・Harness 部品など）、条件（`(state) => boolean` の宣言的な表現。例：`{ type: 'taskCompleted', count: 1 }` `{ type: 'event', name: 'TaskFailed' }`）、解放時に出す文言の ID
   - UI は `isUnlocked(state, featureId)` だけを見て表示・非表示を切り替える
   - 解放時に `FeatureUnlocked` イベントを出す（Tier 2 の演出と「NEW」バッジ）
2. **用語は体験の後に教える（企画書34章）**：`content/glossary.ts` に用語・平易な説明・名前を明かすタイミングを定義する。選択肢は最初は平易な言葉（例：「必要な資料だけ」）で表示し、使った後で「これは Context Routing と呼ばれる」と短いカードで知らせる。
3. **チュートリアル案件 `content/projects/tutorial-lp.ts`**（小さなLP制作。Task 4つ程度）とスクリプト `content/tutorial.ts`
   - 手順はデータで定義する：`{ when: 条件, highlight: 対象, say: 文言ID, allow: 許可する操作 }[]`
   - 流れ：
     1. 「この作業を誰に任せる？」→ 選択肢は Human と Claude の2つだけ
     2. AI に任せると一瞬で終わる（Tier 3：「-3.5 人間時間」）
     3. 次の Task で AI がミスし、品質が低下する（シナリオで確定的に起こす。チュートリアルの seed と強制イベントを使う）
     4. 「AIは速いけど、結果の確認が必要みたい」→ AI→レビューを解放
     5. 「毎回確認するのは大変…」→ 簡易 Eval（自動テスト）を解放 → レビュー時間が激減（Tier 4）
     6. 結果画面（仮）で Profit / Human Hour が大きく上がる
4. **コーチマーク UI**：対象を丸く切り抜いたスポットライト、短い吹き出し、「次へ」ボタンは原則なし（操作すれば進む）。スキップボタンも用意する。
5. **2回目以降の起動**：チュートリアル完了フラグを保存し、タイトル画面から再挑戦できるようにする。

## テスト
- `tests/content/unlocks.test.ts`：全解放の条件と参照先が存在する、循環しない
- `tests/balance/tutorial.test.ts`：チュートリアルの想定どおりの操作列を `runHeadless` で再生すると、各ステップの条件が順番に満たされ、最終的な Profit / Human Hour が開始時の2倍以上になる
- `tests/unit/tutorial-script.test.ts`：各ステップで許可されていない操作が拒否される
- 所要時間：想定どおりの操作列で、ゲーム内時間を1倍速の実時間に換算して3分以内に収まる（テストで計算する）
