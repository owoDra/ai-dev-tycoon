# Phase 07: 演出基盤（ドーパミン設計）

## 目的
企画書42〜45章。「触ると気持ちいい」状態を作る。報酬の大きさに段階を付け、全部が派手になって価値が下がるのを防ぐ。

## 前提
Phase 06

## やること
1. **演出 Tier テーブル（`content/fx.ts`）**：`GameEvent` の種類と条件 → Tier（0〜4）と演出 ID の対応をデータで定義する。Tier ごとにクールダウンと同時再生の上限を持たせる。
   | Tier | 例 | 演出 |
   |---|---|---|
   | 0 | ホバー・押下・選択 | ボタンの押し込み、ハイライト、島がわずかに持ち上がる |
   | 1 | Task 完了 | 島が弾む、コインが数枚飛ぶ、数字がカウントアップ、「✓完了」ポップ |
   | 2 | 自動修復・レビューで問題を発見 | 盾のエフェクト、キャラクターの表情変化、ポップ |
   | 3 | 自動化の導入・ボトルネックの解消・大きな時間削減 | パケットが一斉に流れる、紙吹雪、中央に「-6.4 人間時間」の大きな数字 |
   | 4 | Autonomy Streak の更新・案件完了 | 短い画面フラッシュ、カメラの軽い揺れ、放射状の光、大きなタイポグラフィ |
2. **`fx/director.ts`**：events を購読し、テーブルを引いて演出を起動する。core には依存しない（ViewModel と events だけを見る）。
3. **UI モーション（motion）**
   - `fx/motion.ts`：プリセットの spring とイージング（トークンと同期させる）、`countUp(el, from, to)`、`pop(el)`、`shake(el)`、`morph(before, after)`（Before → After の数字や棒グラフを変形させる）
   - Solid 向けのヘルパー：`use:animate` ディレクティブまたは `<Animated>` ラッパー。出現・退場のトランジション（`Presence` 相当を自作する）
   - 数値表示コンポーネント `<Num value>`：値が変わったら自動でカウントアップし、増減に応じて色付きの「+/-」チップを短く出す
4. **3D VFX（`world/vfx/`）**
   - 共通のパーティクルシステム（InstancedMesh ＋ 寿命・速度・重力・回転。上限とプールを持つ）
   - コインのバースト、紙吹雪、キラキラ、光るリング、パケットの軌跡、放射状の光
   - 島とキャラクターのスカッシュ＆ストレッチ、カメラの揺れ（振幅に上限を設ける）
   - 3D オブジェクトのアニメーションにも motion の `animate()` を使う
5. **コンボ**：短い時間内に Task 完了が続くとコンボ数が増え、演出が少しずつ強くなる（音階は Phase 08 で付ける）。
6. **ヒットストップ風の演出（ただし操作は止めない）**：Tier 4 のときだけ、ワールドの時間を 100ms ほど減速する（シミュレーション自体は止めない）。
7. **Reduce Motion**：`prefers-reduced-motion` と設定画面のトグルに対応する。有効時は scale・揺れ・紙吹雪・フラッシュを無効にし、フェードと即時切り替えに置き換える。テーブル側に `reducedAlternative` を持たせる。
8. **演出のプレビュー画面**（`?dev=fx`）：すべての演出をボタンで発火して確認できる。
9. **D4 への備え**：演出の大きさ・長さ・パーティクル数・カメラの揺れ・フラッシュの強さ、および spring の硬さ（モーションの性格）は、`content/look/feel.ts` のプリセットから読む。実行中に切り替えられるようにし、`?dev=tweak` からも変更できるようにする。この Phase の値は仮の既定値で、D4 で比較して決める。

## テスト
- `tests/unit/fx-table.test.ts`：全 Tier にクールダウンが定義されている、Tier 3 以上は同時に1つだけ再生される、すべての演出に reduced の代替がある
- `tests/unit/director.test.ts`：events を流したときに起動される演出 ID の列（偽の時計を使う）。クールダウン中は抑制される、コンボ数が増える
- `tests/unit/particles.test.ts`：プールの上限を超えて生成しない

## 完了条件
- [ ] プレイ中に Tier 0〜4 の演出が発生し、プレビュー画面ですべて確認できる
- [ ] 演出中でもすべての操作を受け付ける（入力をブロックする要素がないことを、該当するコードで示す）
- [ ] reduced-motion の有効時に代替演出になる
- [ ] パーティクルの最大数で 60fps を維持できるよう、上限値を設定している
- [ ] 上記テストが通る。`npm run check` が exit 0
