# Phase 14: 結果画面・振り返り

## 目的
企画書40章・58〜60章。分析は案件の終了時にまとめて見せる。最初は大きな数字1つと主要3指標だけを出し、「一番効いた改善」「最大の無駄」「次に改善できる場所」を言葉で返して、実務につなげる。

## 前提
Phase 13

## やること
1. **寄与の記録（`core/attribution.ts`）**：計算式で modifier を適用するときに、どの部品や設定がどれだけ人間時間・コスト・品質に影響したかを記録する（記録のコストを抑えるため、Task 単位で集計する）。
2. **反実仮想による評価（`view/retrospective.ts`）**：主要な改善について「それが無かった場合」をヘッドレスで再シミュレーションし、効果を推定する。同じ seed を使い、上位 N 件だけを対象にする。結果画面の表示中に、メインスレッドを止めないよう分割して実行する。
3. **結果画面**
   - 第1段：「🏆 案件完了」は SVG のトロフィーに置き換える。Profit / Human Hour の大きなカウントアップと、前回比・初回比の「+183%」（Tier 4）
   - 第2段：主要3指標（人間時間・AIコスト・品質）を、Before → After の変形アニメーションで表示する
   - 第3段：「詳しく見る」で、一番効いた改善・最大の無駄・次に改善できる場所の3枚のカードを出す（文言のテンプレートは i18n）
   - 第4段（上級者向け）：工程別の時間、介入の時系列、AIコストの内訳。グラフは少数にとどめ、ダッシュボードのようにしない
   - ランク評価（S / A / B / C）とスタンプの演出。基準は `balance.ts` に置く
4. **Workflow の保存の導線**：「この構成を保存する」ボタン（実際の保存は Phase 16。この Phase ではボタンと、データとして書き出す部分まで作る）
5. **キャンペーン全体の結果画面**：全案件を通した成長の推移（人間時間の減少と Profit / Human Hour の上昇）

## テスト
- `tests/unit/attribution.test.ts`：寄与の合計が全体の差分とおおむね一致する（許容誤差つき）
- `tests/view/retrospective.test.ts`：Eval を入れた構成では「一番効いた改善」に Eval が選ばれる、不要な資料を大量に渡した構成では「最大の無駄」に Context が選ばれる
- `tests/view/rank.test.ts`：ランクの境界値

## 完了条件
- [ ] 案件の終了時に4段構成の結果画面が出て、各段が段階的に開示される
- [ ] 振り返りの3枚のカードが、プレイ内容に応じて妥当な内容になる（テストで担保する）
- [ ] 上記テストが通る。`npm run check` が exit 0
