# Phase 35: 受注の見直し

## 目的
受注を運に任せず、会社の規模に合った案件の中から選ぶ判断にする。

## 前提
Phase 34

## 決定済みの方針（2026-10-28 ユーザー回答）
- コンペ・見積・失注・見送りをなくし、一覧から選べば必ず受注できる
- 会社の規模で受けられる案件を絞る。同時に進められる数は規模ごとの上限まで

## やること
1. 引き合いを「受注できる案件」にする。報酬・期限・規模・契約の種類を見て選ぶだけ
2. 規模ごとの同時進行の上限を `balance.ts` に持つ
3. 見積・勝率・コンペの結果の UI と core を取り除く。評判は届く案件の質（報酬）に効かせる

## テスト
- `tests/unit/`：規模に合わない案件が届かない、上限を超えて受注できない、選べば必ず受注
- `tests/balance/`：入札の前提のテストを、新しい受注の仕組みで表し直す

## 完了条件
- [ ] 失注がない
- [ ] 規模ごとの案件と同時進行の上限が効く
- [ ] `npm run check` が exit 0
