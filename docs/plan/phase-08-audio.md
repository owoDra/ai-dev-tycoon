# Phase 08: オーディオエンジン

## 目的
音声ファイルに頼らず、Web Audio だけでリッチでプロダクトらしい質感の音を作る。音は補助であり、ミュートしても情報は失われない（企画書46章）。

## 前提
Phase 07（演出 director が events を Tier に変換している）

## やること
1. **ミキサーグラフ（`audio/engine.ts`）**
   ```
   SFX bus ─┐
   UI bus  ─┼─► Master EQ ─► Compressor/Limiter ─► Destination
   Music bus┘      ▲
   Reverb send ────┘   （ConvolverNode。インパルス応答はノイズと減衰エンベロープから起動時に生成する）
   ```
   - サイドチェイン風のダッキング：Tier 3 以上の効果音が鳴っている間は、Music bus の音量を一時的に下げる
   - 最初のユーザー操作で AudioContext を resume する（自動再生の制限への対応）
2. **シンセの音源（`audio/synth/`）**：FM、減算合成（ノコギリ波 ＋ フィルタのエンベロープ）、Karplus-Strong の撥弦音、ノイズのパーカッション、ベルの加算合成、キック・スネア・ハイハット
3. **効果音カタログ（`content/sfx.ts`）**：効果音の ID → レイヤー構成（音源・音程・エンベロープ・フィルタ・パン・センド量）をデータで定義する
   - UI：ホバー（ごく小さく）、クリック、トグル、パネルの開閉
   - ゲーム：Task の開始と完了、コイン（音程の違う複数のベルを重ねる）、コンボ（ペンタトニックの音階を1段ずつ上げる）、警告、失敗、自動修復、ボトルネックの解消、大成功のファンファーレ（短い和音の進行）、Autonomy Streak（上昇するアルペジオ ＋ シマー）
   - 単調にならないよう、再生のたびに音程や音量にわずかな揺らぎを加える
4. **事前レンダリング**：複雑な効果音は起動後のアイドル時間に `OfflineAudioContext` で AudioBuffer に焼き込み、再生時の CPU 負荷を下げる
5. **立体音響**：ワールド内の出来事による効果音は、画面上の位置に応じて StereoPanner でパンを付ける
6. **アダプティブ BGM（`audio/music/`）**
   - ステップシーケンサー（先読みスケジューリング方式。lookahead 約100ms）
   - コード進行・ベース・パッド・アルペジオ・ドラムのレイヤーを、ゲームの「勢い」（流れている Task の量・コンボ・Autonomy）に応じて足したり減らしたりする
   - 一時停止中はローパスフィルタで音をこもらせ、結果画面では別の曲調にする
   - 楽曲のデータ（スケール・進行・パターン）は `content/music.ts` に定義する
7. **`fx/director` との連携**：演出 ID と効果音 ID の対応は `content/fx.ts` 側に持たせる（演出と音を同じ場所で調整できるようにするため）
8. **設定**：マスター・効果音・BGM の音量、ミュート。初期値は控えめにし、localStorage に保存する（try/catch で囲む）
9. **サウンドテストの画面**（`?dev=audio`）：すべての効果音と BGM の各レイヤーを試聴できる
10. **D4 への備え**：音色（音源の種類・倍音・リバーブ量など）を「音色のパレット」としてプリセット化し、効果音カタログと楽曲データはパレットを参照する形にする。実行中に切り替えられるようにする。この Phase のパレットは仮の既定値1種でよく、D4 で比較して決める。

## テスト
- `tests/unit/sfx-catalog.test.ts`：全 ID のレイヤー構成が有効である（周波数が可聴域内、エンベロープの合計時間が上限以内、ピーク音量の合計が 1 を超えない）
- `tests/unit/sequencer.test.ts`：スケジューリングされるノートの時刻がテンポと一致する、ドリフトしない（偽の時計を使う）
- `tests/unit/music-intensity.test.ts`：ゲームの勢いの値に対して、有効になるレイヤーが単調に増える
- AudioContext に依存する部分は薄くし、計算部分を純粋関数に分けてテストする
