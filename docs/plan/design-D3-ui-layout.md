# D3: 画面構成

## 決めること
Phase 06 で作る UI の配置と、操作の流れ。PC とスマホの両方について決める。

- HUD の位置と見せ方（上部の帯 / 四隅に分散 / 下部のドック）
- 選択したものの詳細の出し方（右サイドパネル / 選んだ島の近くに出るポップオーバー / 下からのシート）
- 「次に対応すべき問題」の出し方（下部の固定カード / 右上に積み重なるトースト / キャラクターの吹き出し）
- 担当変更の操作（ラジオ式のリスト / 大きなカードから選ぶ / 円形メニュー）
- スマホでの縦構成

## 前提
D2（ワールドの見せ方が決まっていること）

## 探索で作るもの
- 3つのレイアウト案を `content/look/layout.ts` のプリセット、または `src/dev/explore/layouts/` のコンポーネントとして作る。この時点では本実装ではなく、**実際のワールドと仮データの上で操作できるプロトタイプ**にする（島を選ぶ → 詳細が出る → 担当を変える → 問題カードから島へ移動する、という一連の操作を試せること）
- 案の方向性の例
  - A：右サイドパネル＋上部 HUD＋下部の問題カード（情報の見通しを重視）
  - B：選んだ島の近くに出るポップオーバー＋四隅の HUD＋トースト（ワールドへの没入を重視）
  - C：下部ドック＋下からのシート（ゲームらしさとスマホ対応を重視）
- 各案に PC（1440px）とスマホ（375px）の両方の表示を用意し、比較ページで幅を切り替えられるようにする
- 各案で、HUD に常時表示する項目が5つ以下であることを確認できるようにする

## 反映でやること
- 採用したレイアウトを Phase 06 の実装方針として確定する。プロトタイプのコードは Phase 06 で本実装に置き換えるため、ここでは採用案の構造（領域・ブレークポイント・操作の流れ）を `content/look/layout.ts` の型と既定値として残し、不採用の案を削除する
- `docs/decisions/D3-ui-layout.md` に、採用内容・理由・あなたのコメント・URL を記録する
