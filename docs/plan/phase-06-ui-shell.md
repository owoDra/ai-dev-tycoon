# Phase 06: UI シェル

## 目的
企画書29〜41章・52〜56章の UX 原則に沿って、3Dワールドの上に重なる UI を作る。「1画面1目的」「全部見せない」を徹底する。

## 前提
D3（レイアウトの構造が `content/look/layout.ts` の既定値として決まっていること）。配置・詳細の出し方・問題カードの出し方・担当変更の操作は、D3 の決定に従う。以下の項目のうち配置に関わる記述は、D3 の決定を優先する。

## やること
1. **画面遷移（`app/screens.ts`）**：タイトル → 案件選択（今は1件）→ プレイ → 結果（仮）。遷移には motion を使う（Phase 07 で強化する）。
2. **タイトル画面**：キービジュアル（WebP）と 3D ワールドのアイドル表示を組み合わせ、「なんか楽しそう」と感じられる第一印象を作る。
3. **HUD（常時表示は最大4〜5項目）**：Profit / Human Hour、残り時間（営業日と時刻）、人間とAIの稼働バー、一時停止と速度切り替え。数字はアイコン・ラベルと組み合わせて表示する。
4. **「次に対応すべき問題」カード**（画面下部）：`view/advice.ts` が最も重要な問題を1つだけ選んで出す（今はボトルネックだけでよい）。「問題 → 原因 → 次の行動」の3段構成にし、ボタンを押すと該当する島を選択してカメラを寄せる。
5. **選択時の詳細パネル**（企画書33章）：選んだ Task または人の情報（担当・状態・品質の見込み）と、担当変更のラジオ式の選択肢（Human / AI / AI→レビュー など。解放されたものだけ表示する）。表示位置は D3 の決定に従う。
6. **担当変更のプレビュー**：選択肢にフォーカスやホバーをすると、変更後の予測（人間時間・AIコスト・品質）を Before → After で表示する。予測には `core` のヘッドレス実行を使う（短い期間だけのシミュレーション）。`view/forecast.ts` に置く。
7. **3D 上のラベル**：島の上に名前と状態アイコンを DOM のオーバーレイとして重ねる（`world.project` を使う）。
8. **トースト / ポップアップの基盤**：短い文言で出し、操作を妨げない（企画書44章）。
9. **キーボード操作**：Tab でフォーカス移動、Enter で決定、Esc でパネルを閉じる、矢印キーで島を移動、Space で一時停止。フォーカスリングを明確に表示する。
10. **レスポンシブ**：PC・タブレット・スマホ。ブレークポイントと各幅での構成は D3 の決定に従う。
11. **i18n**：UI の文言はすべて `i18n/ja.ts` に置き、短いコピーにする（企画書63章）。
12. **クリック領域**：主要な操作は 44px 以上、それ以外も最低 24px にする。

## テスト
- `tests/view/advice.test.ts`：ボトルネックがあるとき、最優先の問題として選ばれる
- `tests/view/forecast.test.ts`：レビューを外すと人間時間が減り、品質の見込みが下がる、という方向の予測が出る
- `tests/ui/*.dom.test.tsx`（最小限）：HUD に表示する項目数が上限以内であること、詳細パネルが Esc で閉じること
