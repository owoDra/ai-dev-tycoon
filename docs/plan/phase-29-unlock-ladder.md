# Phase 29: 機能の段階的な解放

## 目的
企画書50章の「必要になる前に説明しない」「順番に解放する」に沿って、Workflow・Harness・Context などを、プレイヤーが必要を感じた後に1つずつ渡す。

## 前提
Phase 28

## 現状（2026-10-28 調査）
- チュートリアルの案件を納品した瞬間に9件、その後の約1営業日でさらに6件以上が解放される（`content/unlocks.ts`）
- チュートリアル直後の工程画面に、Workflow の候補（どれも見込み利益マイナス）・Library・Harness の入口が並ぶ
- MCP と権限モードは Agent Workflow を一度完了しないと解放されず、序盤に選ぶ理由のないモードなので一生解放されないことがある
- 採用とチームは、引き合いの少ない個人事業の間はほとんど効かない

## やること
1. **解放のはしご**：問題を体験した後に、その解決策を渡す順に並べ直す
   - 人間 → AI：2件目の納品
   - Context：資料のある案件で AI のミスが起きた後
   - Harness（Skill・Hook）：人間のレビューを繰り返した後
   - Agent Workflow と Workflow の候補：Harness を使った後
   - 採用：引き合いが人手を上回ってきた後
   - Subagent・チーム・MCP・権限モード：スタートアップへの昇格
   - Mod・Routine：小規模企業への昇格
2. **1営業日に1つ**：条件を満たした解放が重なったら、1営業日に1つずつ渡す（関連する機能は同じ日にまとめる）
3. **未解放の部品を含む Workflow の候補は出さない**
4. 解放の条件に、会社の規模（`tier`）と、Harness の部品を付けた回数を足す

## テスト
- `tests/unit/unlocks.test.ts`：チュートリアル直後に Workflow・Harness が解放されていないこと、1営業日に1つずつ解放されること
- `tests/balance/`：上手な Bot が60営業日で主要な機能をすべて解放できること

- [ ] チュートリアル直後の工程画面に Workflow・Harness が出ない
- [ ] どの遊び方でも、MCP と権限モードが解放される
