# Phase 22: 長く遊べるようにする

## 目的
クリアのない経営を、長く遊び続けられるようにする。区切りと目標をつくり、成長が止まったり壊れたりしないことをテストで保証する。

## 前提
Phase 21

## やること
1. **決算**：四半期ごと（例：60営業日）に決算を出す。売上・利益・利益 / 人日・評判・規模を前期と比べ、結果画面の4段構成を決算向けに作り直す。結果コードは決算ごとに出す
2. **目標と実績**：次の規模への昇格条件を常に示す。実績（例：「AI PM だけで XL 案件を納品」）を content のデータで定義し、達成を記録する
3. **後半の要素**：大規模案件ほど Harness・Context・Workflow Library の効果が大きくなるよう、生成のパラメータを調整する。後半の事件（大規模障害・人材の引き抜き・競合の値下げ）を加える
4. **セーブ・隙間時間の遊び方**：長期のセーブ（形式のバージョン管理）、閉じている間の進行・あらすじを、複数チームと決算に合わせる
5. **長期のバランステスト**：自動戦略で数年分をヘッドレスで回し、次を確かめる
   - 上手な戦略は規模が昇格し続け、下手な戦略は伸び悩む（ただし即座には破産しない）
   - 利益 / 人日 が後半ほど AI の活用で伸びる
   - 1つの戦略（モード・構成・見積の方針・PM の種類）が常に最適にはならない
   - 長時間回しても性能（1ステップの処理時間・state の大きさ）が上限に収まる
