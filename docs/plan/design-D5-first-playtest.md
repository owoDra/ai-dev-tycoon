# D5: 最初の3分の通しプレイ

## 決めること
Phase 09 で作ったチュートリアルを実際に遊び、テンポ・文言・分かりやすさ・気持ちよさを調整する。ここで手触りが固まれば、以降の Phase は内容を足していく作業が中心になる。

## 前提
Phase 09

## 準備で作るもの
- **プレイログ**（開発用。`?dev=log` のときだけ有効）：チュートリアルの各ステップに到達した実時間、迷った時間（操作がなかった時間）、誤って押した操作、スキップの有無を記録する。終了時に JSON としてコピーできる
- **フィードバックの観点**：プレイ前に読んでもらうチェックリストを会話に出す（例：「最初の10秒で何をすればいいか分かったか」「AI に任せたときに気持ちよかったか」「ミスが起きたとき、何が悪かったか分かったか」「Eval の解放時に名前と効果が結び付いたか」「長いと感じた場面」）
- 気付いた課題の候補を、Claude 自身もヘッドレスでのテンポ計測から事前に列挙しておく

## フィードバックの返し方
- AskUserQuestion の質問に、観点ごとの感想とプレイログの JSON をメモ欄で回答する（Artifact のコメントでもよい）

## 反映でやること
- フィードバックを「文言」「テンポ（時間・待ち）」「演出」「操作」「分かりやすさ」に分類し、それぞれ対応する
- 文言は `i18n/ja.ts`、テンポは `content/tutorial.ts` と `balance.ts`、演出は `content/fx.ts` を調整する。原則としてデータの変更で対応する
- `tests/balance/tutorial.test.ts` の3分以内の条件を引き続き満たす
- `docs/decisions/D5-first-playtest.md` に、主なフィードバックと対応内容を記録する

## 準備・反映プロンプト（通常はこれを使う）
```
/goal docs/plan/README.md（特に8章）と docs/plan/design-D5-first-playtest.md を読み、D5「最初の3分の通しプレイ」を準備からフィードバックの反映まで行う。プレイログ機能（?dev=log）を実装し、チュートリアルを通しで遊べるビルドを Artifact に公開する。フィードバックの観点チェックリストを会話に示した後、AskUserQuestion で私のプレイ結果を質問する（選択肢: フィードバックあり（メモ欄に感想とプレイログを書く） / 問題なし / ビルドを作り直してほしい）。フィードバックを受け取ったら分類して対応し、同じ URL に再公開して、再プレイの確認を AskUserQuestion で取る（何回でもよい）。完了条件（すべて会話内で示すこと）: (1) フィードバックの観点チェックリスト（5〜8項目）と、ヘッドレスで計測した各ステップの所要時間を示している (2) Artifact の URL と、プレイログを有効にする方法（ローカルでの確認手順を含む）を示している (3) AskUserQuestion で私がフィードバックを回答し、最後の確認で「問題なし」と回答している (4) フィードバックを分類（文言・テンポ・演出・操作・分かりやすさ）し、各項目の対応内容と変更したファイルを表で示している。対応しなかった項目は理由を示している (5) tests/balance/tutorial.test.ts が pass し、想定どおりの操作列での所要時間が3分以内であることを出力で示している (6) docs/decisions/D5-first-playtest.md に主なフィードバックと対応、Artifact の URL を記録している (7) `npm run check` が exit code 0 で終わった出力の末尾を示している (8) 変更を「D5: ...」というメッセージでコミットし、`git status --short` が空であることを示している。制約: コマンドは project/ ディレクトリで実行する。私への質問は文章でターンを終えず、必ず AskUserQuestion を使う。フィードバックと関係のない変更を加えない。テストの判定条件を緩めない。docs/plan/ は変更しない。60ターンで未達なら作業を止め、現状と残課題を報告する。
```
