# Phase 43: 育つハーネスをプラグインとして持ち帰る

## 目的
ゲームで組んで育てたハーネスを、本物の Claude Code でそのまま入れられるプラグインとしてダウンロードできるようにする。
ゲームを進めるほど、持ち帰れるハーネスの中身が増える。
Phase 42 と合わせて、「持ち込む → ゲームで鍛える → 持ち帰る」の循環を作る。

## 前提
Phase 42

## 決定済みの方針（2026-10-29 ユーザー回答）
- 実務モードの作り直しは、案A（Phase 42）と案B（プラグインの書き出し）で進める

## やること
1. **プラグインの最新の形を確認する**
   - `plugin.json` の項目・skills・agents・hooks・MCP の置き場所を確認し、確認した内容をコードの型とコメントに書く
   - 作業の初めに、claude-code-guide のエージェントか公式のドキュメントで確認する
2. **書き出す元をゲームの進み具合にする**
   - 今の書き出し（`core/harnessExport.ts`）は、実務モードの入力から作っている。これを土台に、次のものから作る：
     - Workflow Library に保存した Workflow
     - 解放した部品
     - 持ち込みカード（Phase 42）
   - 持ち込みカードは、読み込んだ元の中身をそのまま戻す（ゲームの評価で書き換えない）
   - 同梱の部品の中身（`content/harness/export.ts`）は汎用の雛形として整え、そのまま使えるものにする
3. **ハーネスが育つ**
   - 解放や会社の規模に応じて、書き出せる部品が増える
   - Workflow をゲーム内で使った回数と稼いだ利益を記録し、プラグインの README に「ゲーム内の成績」として書く
   - 書き出しの画面に、ハーネスのレベル（入っている部品の数や種類）と、次に増える部品を出す
4. **ダウンロード**
   - プラグインのフォルダ一式を1つの zip にまとめてダウンロードする。zip は外部依存なしで作る（無圧縮か `CompressionStream`）
   - 入れ方（ローカルのフォルダからプラグインを入れる手順）を、画面と README に書く
   - 中身は汎用の雛形を含むことを、画面と README ではっきり示す
5. **入口**
   - 会社のメニューと結果画面から開く
   - Phase 42 の「持ち込み」の画面からも開く

## 完了条件
- [ ] 書き出したファイルの一覧と、`plugin.json`・`hooks.json`・各 `SKILL.md` の形が正しいことを確かめるテストがある
- [ ] ゲームを進めた状態（解放・Workflow の数が多い）では、序盤より書き出す部品が多いテストがある
- [ ] 持ち込みカードを書き出すと、元の中身と同じになるテストがある
- [ ] zip を自前のコードで読み戻すと、同じファイルの一覧と中身になるテストがある
- [ ] 書き出したプラグインを本物の Claude Code に入れて読み込めたことを確認し、その手順と結果を報告する
- [ ] `npm run check` が exit 0（単一 HTML・外部参照なし・サイズ予算内）
