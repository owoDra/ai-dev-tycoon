# Phase 42: 持ち込み評価（自作の Claude Code の設定をゲームの部品にする）

## 目的
実務モード（業務を入力して ROI を試算する）を、懇親会で開く理由のあるモードに置き換える。
自分が普段使っている Claude Code の設定（Skill・Subagent・Hook・MCP・CLAUDE.md・Rules・プラグイン）を読み込むと、ゲームが評価して Harness の部品（持ち込みカード）にする。持ち込んだ部品は、ゲーム内の AI に付けて使える。
持ち寄った部品で同じ案件の利益を競う「持ち寄りバトル」を、懇親会モードに乗せる。

## 前提
Phase 41

## 決定済みの方針（2026-10-29 ユーザー回答）
- 実務モードの作り直しは、案A（持ち込み評価）と案B（Phase 43：プラグインの書き出し）で進める
- 作業ログの再生（C-1）と、本物の Claude Code とのリアルタイムの連動（C-2）は今回は作らない

## やること
1. **読み込み**（ブラウザの中だけで行う。外部に送らない）
   - 入口は4つ：フォルダの選択、ドラッグ&ドロップ、zip、単一のファイル
   - 読むのは決まったファイルだけにする：`SKILL.md`・`agents/*.md`・`settings.json`（hooks・permissions）・`.mcp.json`・`CLAUDE.md`・`.claude/rules/*.md`・`plugin.json`・`hooks.json`
   - ファイルの大きさと数には上限を置く
   - zip はブラウザ標準の `DecompressionStream('deflate-raw')` と、自前の zip の目次の読み取りで展開する（外部依存なし）
   - 読み込んだ中身はテキストとして扱う。スクリプトは実行せず、HTML として描画しない
   - トークンや鍵に見える文字列（`.env` の中身など）を見つけたら、警告して保存しない
2. **評価**（`core/` の純粋関数。同じ入力からは同じ結果を返す）
   - ファイルの種類から部品のカテゴリを決める（Skill・Subagent・Hook のタイミング・MCP・権限・CLAUDE.md・Rules）
   - 書き方の良さを、カテゴリごとの観点で点にする。観点の例：
     - Skill：description に「いつ使うか」がある・手順が具体的・長すぎない
     - Subagent：役割と使える道具が絞られている
     - Hook：テストや lint などの確認を動かす・matcher が絞られている
     - 権限：deny がある・危ない許可がない
     - CLAUDE.md：長さが目安の範囲内（長すぎると Noise）
     - MCP：数が多すぎない
   - 点をゲーム内の補正（`HarnessModifiers`）・コスト・効く Task の種類に変換する。上限と変換の係数は `content/balance.ts` に置く
   - 「持ち込んだ設定が強すぎてゲームが壊れる」ことを防ぐため、同じカテゴリの最も良い同梱部品を大きく超えない。これをバランステストで確かめる
3. **持ち込みカード**
   - 評価の結果を、Harness Builder で同梱の部品と同じように付け外しできる部品としてセーブに保存する
   - カードには元の名前と、評価の理由を出す（良かった点・伸ばすと強くなる点）。「なぜこの性能？」は Phase 27 の内訳の出し方にそろえる
   - 解放の順番：Harness Builder が解放された後に使える
4. **持ち寄りバトル**（Phase 15 の懇親会モードに乗せる）
   - 同じ Seed の案件で、各自の持ち込みカードを使って利益を競う
   - 結果コードに、使った持ち込みカードの要約（カテゴリと点。中身は含めない）を入れる
5. **実務モードの入口を置き換える**
   - タイトルの「実務モード」を「持ち込み」に変える
   - 今の試算の画面を残すか（サブのタブにする）、なくすかは、作業の始めに AskUserQuestion で確認する
   - `core/practice.ts` と既存のテストは消さない（Phase 43 の書き出しでも使う）
