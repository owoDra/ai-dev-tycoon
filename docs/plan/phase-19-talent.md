# Phase 19: 人材の自動生成と採用

## 目的
社員を固定の5人から、**seed で生成されるさまざまな能力の人材**に置き換える。採用で会社の人員が増え、単価（売値）と原価が人によって違うことが経営判断になる。

## 前提
Phase 18

## やること
1. **人材の生成（`core/talent.ts`、`content/talent.ts`）**
   - 名前（姓名の組み合わせ）・職種・速度（skill）・正確さ・得意分野（0〜2個）・売値・原価を seed から生成する
   - 売値は能力から決める。人日あたり **下限5万・平均8万**。能力の分布と係数は balance に置く
   - 人材の id から定義を決定論的に再生成できる形にする（例：`h~<seed>`）。`getHuman` は生成した id も解決する。state には id だけを持つ
   - 正確さを人間の成功確率に反映する（今は全員 `competence` が同じ）
2. **採用市場**
   - 営業日ごとに候補が入れ替わる（数は会社の規模で増える。規模は Phase 21 で入れるので、この Phase では固定値）
   - Command：`Hire`（契約金を払って入社）・`Release`（退職。進行中の工程があればできない）
   - 人員の上限は balance の固定値にしておく（Phase 21 で会社の規模から決める）
3. **初期メンバー**：ゲーム開始時に、平均的な能力の2人を seed から生成する（チュートリアルは今の固定の2人のまま）
4. **社員の画面**：売値・原価・速度・正確さ・得意分野を、アイコンとラベルで比べられるようにする。採用候補のタブを追加する

## テスト
- `tests/unit/talent.test.ts`：同じ seed なら同じ人材になる、id から再生成すると一致する、売値が下限以上
- `tests/balance/talent.test.ts`：大量に生成したときの売値の平均が8万前後、下限5万を下回らない、能力と売値が相関する
- `tests/unit/hire.test.ts`：採用・退職の Command、上限、作業中は退職できない

## 完了条件

- [ ] 採用と退職ができ、セーブして再開しても人材が一致する
