# AI業務改善タイクーン（仮）企画書

## 1. 企画概要

### コンセプト

**AIをたくさん使うゲームではなく、AIを適切な仕事へ配置し、人間1人あたりの生産量と利益を最大化するゲーム。**

プレイヤーはWeb制作会社の案件を担当し、

- 人間に任せる
- Claudeへ任せる
- AI → 人間レビューにする
- Workflow化する
- Agentを並列稼働する
- Standard / Premiumシートを配置する
- モデルを使い分ける
- Contextを整理する
- Skill / Hook / Evalを導入する

といった判断を行う。

目標はAI利用量ではない。

**同じ人数・同じ時間から、より多くの高品質な仕事と利益を生み出すこと**

を目指す。

---

# 2. 解決したい課題

すでにClaude Teamを全社導入しているため、

> AIを使いましょう

というフェーズではない。

対象とする問題は、

> Claudeを日常的に使っているが、一人あたりの仕事量や利益率が十分に上がっていない

こと。

原因として、

- 単発作業の高速化だけで終わっている
- 人間中心の業務フローをそのまま高速化している
- AI化後に別工程がボトルネックになる
- 高性能モデルを必要以上に使用する
- AI成果を人間が毎回すべて確認する
- 毎回同じ指示を入力している
- 不要なContextを大量に与えている
- AIの失敗を防止・検出する仕組みがない
- 良い活用方法が個人ノウハウで終わっている

といった問題をゲーム化する。

**AIが働くことを前提に会社の仕事の流れそのものを再構成する。**

# 5. 人間とAIへの配置

各仕事について、

### Human

時間は掛かるが安定。

### AI

高速だが誤りの可能性がある。

### AI → Human Review

AIへ大部分を委譲して人間は確認だけ。

### Human → AI

重要判断だけ人間が行って残りを委譲。

### Agent Workflow

複数工程を自動的につなげる。

から選択する。

# 6. Claude Teamを経営資源にする

Claude Teamのシートもゲーム資源とする。

2026年10月時点では、TeamのStandardは米国価格で月払い$25、年払い換算$20/月。Premiumは月払い$125、年払い換算$100/月。組織内でStandardとPremiumを混在でき、Premiumはより高い利用上限を持つ。

例えば、

| Member | Seat | Work |
|---|---|---|
| PM | Standard | 要件・顧客対応 |
| Designer | Standard | UI |
| Developer A | Premium | Agent運用 |
| Developer B | Premium | 実装 |
| QA | Standard | QA |

のように配置する。

全員Premiumにすれば強いとは限らない。

固定費と利用状況を考慮して、

**誰に高価なAI容量を割り当てれば会社全体の生産性が最大化するか**

を考える。

      ×
    Harness

**高いモデルを買えば勝ち**

# 9. Contextを有限資源にする

画面には必要最小限のContext状態を表示する。

    CONTEXT

    ████████████░░ 72%

    Relevant  58%
    Noise     14%

大量の情報を与えるほど強いわけではない。

例えば、

- 古い仕様
- 無関係なIssue
- 重複ドキュメント
- 過去案件
- 相互矛盾したルール

を投入するとNoiseが増える。

Noiseが増えると、

- AI消費量増加
- 誤判断率上昇
- 古い仕様参照
- Tool誤選択

などが起きる。

# 10. Context Router

Taskに必要な情報だけを渡す。

例えば、

    決済画面の修正
          ↓
     Context Router
          ↓
    決済仕様
    関連コード
    関連テスト
    Coding Rules

だけを選択する。

50資料すべてをAIに与えるより、

**必要な4資料へ絞る方が強い**

ゲームバランスにする。

---

# 11. Session Reset / Handoff

長いSessionではContext Noiseが増える。

    Context 94%
    Noise   37%

`NEW SESSION`

すると、

    Context 8%
    Noise   0%

になる。

しかし単純にResetすると、

    ⚠ Important Decisions Lost

が発生する。

そこで、

### Handoff

    Goal
    Decisions
    Constraints
    Modified Files
    Validation
    Remaining Work

だけを次のAgentへ渡す。

これにより、

**履歴全部を持つことと、必要な作業状態を残すことは違う**

と体験させる。

# 19. Harness由来のゲームイベント

技術的な問題を「敵」として登場させる。

### Context Overflow
不要情報過多。

### Stale Context
古い情報を参照。

### Instruction Conflict
ルール同士が衝突。

### Retry Spiral
Agentが失敗を繰り返す。

### Agent Drift
目的から逸脱。

### Missing Validation
誤った成果物を完成扱い。

### Coordination Explosion
Subagent過多。

### Human Bottleneck
AIは速いが人間確認で停止。

# 34. Recognition over Recall

プレイヤーへ用語を暗記させない。

NN/gは、人間に記憶から情報を思い出させるより、画面から選択肢を認識できるUIの方が認知負荷が低いとしている。

例えば、

> Context Routerとは？

を覚えさせるのではなく、

    AIに渡す情報

    ○ 必要な資料だけ
    ○ すべての資料

のような選択から始める。

選択後、

> 「必要な資料だけを選ぶ仕組みはContext Routingと呼ばれる」

と名称を後から教える。

**概念 → 用語**

ではなく、

**体験 → 用語**

の順にする。

# 44. Animationを待たせない

Animation中でも次の操作を可能にする。

Apple HIGも、Animation完了まで操作を強制的に待たせることを避けるよう推奨している。

結果演出は、

**操作を止めない気持ちよさ**

を優先する。

---

# 45. Reduce Motion

OSの、

    prefers-reduced-motion

を尊重する。

有効時には、

- Scale
- Bounce
- 大移動
- 点滅

を削減し、

Fadeや即時切替へ変更する。

Appleも、重要情報をMotionだけで伝えず、Reduce Motionへ対応することを推奨している。

---

# 46. Sound Design

Web Audio APIで、

- 完了
- 大成功
- Warning
- Combo
- Money

などの短い音を生成する。

しかしAudioは補助。

音を消してもゲーム情報を失わない。

初期状態では控えめな音量とする。

---

# 47. フィードバック

操作した瞬間に必ず反応する。

例えばPremiumへ変更：

    Premiumへ変更

        ↓

    AI Capacity
    +400%

    Cost
    +¥XX,XXX / month

を即座にPreviewする。

確定後：

> ✓ Premiumへ変更

と表示する。

AppleのFeedbackガイドでも、現在状態、操作の成功・失敗、問題の修正方法を明確に伝えることが重要とされている。

---

# 48. Before / After Preview

重要な変更では結果を確定前に見せる。

例えば、

    QA Agent

    Current
    Human 3.0h

        ↓

    Predicted
    Human 0.5h
    AI Cost +¥1,200

    [導入する]

とする。

「何が起きるか分からないButton」を減らす。

---

# 49. Error UX

エラー時に、

> ERROR 104

のような表示はしない。

例えば、

> ⚠ AIのContextに古い仕様が混ざっています

その下へ、

> 古い資料を外すと成功率が改善します。

さらに、

    [Contextを見る]

を表示。

**問題 → 原因 → 次の行動**

まで1画面で分かるようにする。

---

# 50. Tutorial

長い説明画面は作らない。

最初の案件そのものをTutorialにする。

最初：

    この作業を誰に任せる？

    👤 Human
    🤖 Claude

だけ。

次に、

> AIは速いけど結果の確認が必要みたいです。

としてReviewを解放。

次の案件で、

> Contextが増えて精度が落ちてきました。

としてContext Managementを解放。

さらに、

- Skill
- Hook
- Subagent
- Eval

を順番に解放する。

**必要になる前に説明しない。**

---

# 51. 最初の3分

初回起動から3分以内に、

    Humanだけ
        ↓
    AI導入
        ↓
    作業時間激減
        ↓
    AIミス発生
        ↓
    Harness改善
        ↓
    さらに改善

まで体験させる。

開始直後に、

> Harness Engineeringとは……

という解説はしない。

ゲームとして問題を体験した後で名前を教える。

# 52. 操作方法

基本操作は、

**Click / Tap中心**

とする。

Drag & Dropを必須にしない。

例えばTaskの担当変更も、

    担当

    ○ Human
    ● Code Agent
    ○ QA Agent

から変更可能。

Drag & Dropは補助操作として提供してもよい。

WCAG 2.2でもDraggingを必要とする機能には、Drag以外の操作方法を提供することを要求している。

---

# 53. Click Target

ButtonやCardは十分大きくする。

最低限WCAG 2.2の24×24 CSS pxを満たし、主要操作についてはそれよりかなり大きく取る。

特に、

- Task Card
- Agent
- Primary Button
- Model選択

などは小さなIconだけにしない。

---

# 54. Contrast

本文はWCAG AAを基準とし、

通常文字：

    4.5 : 1

以上を確保する。

淡い色を多用するPop UIでも、

**文字まで淡くしない。**

背景は柔らかく、文字ははっきり。

を基本にする。

# 55. Keyboard

マウスだけでなくKeyboardでも基本操作可能とする。

    Enter
    Escape
    Arrow

など標準的な操作を優先。

独自Shortcutを覚えなくても遊べる。

Shortcutは上級者向け補助機能にする。

# 56. Responsive

ただし単一HTMLなので、

- Tablet
- Mobile

でも崩れないレスポンシブ構成にする。

       ↓
    Selected Task
       ↓
    Actions

の縦構成へ変更。

# 64. UX設計原則まとめ

本作のUIでは、

### 必要になった時だけ見せる

Progressive Disclosure。

### 覚えさせない

Recognition over Recall。

### 1画面1目的

現在の判断に集中。

### 操作結果を即座に返す

Immediate Feedback。

### 数字より意味

Good / Warningなどを先に表示。

### 色だけに頼らない

Icon + Labelを併用。

### Motionは報酬と理解補助

装飾目的では使わない。

### Expert機能は残す

Simple ≠ Feature Removal。

を基本原則とする。

Appleも2026年のDesign Principlesで「SimplicityはMinimalismではなく、必要なものを必要な場所に置くこと」としている。
