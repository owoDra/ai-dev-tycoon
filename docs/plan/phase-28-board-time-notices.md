# Phase 28: 案件ボードの締切・時間の流れ・通知の見直し

## 目的
引き合いや受注した案件を、プレイヤーが気付く前に失わないようにする。古い通知や、一度に出て一瞬で消える通知をなくす。

## 前提
Phase 27

## 決定済みの方針（2026-10-28 ユーザー回答）
- 引き合いの締切：**締切を延ばし、ボードを開いている間は時間を止める**（Phase 24 の「当日確定」を改める。結果を待つだけのときの早送りは残す）
- 範囲：Phase 28〜30 をすべて実装する

## 現状（2026-10-28 調査）
- 引き合いは 10:00 に届き、同じ日の 17:00 に締め切る。1倍速で実時間17.5秒、10倍速で1.75秒。ボードを開いても時間は進む
- 見送った引き合いは通知（2.6秒）だけで、結果の履歴に残らない
- 標準の納期が1〜2日の案件（引き合いの約4割）は、`Math.round` で短縮・標準・余裕が同じ日数になる
- 閉じている間の進行（`core/away.ts` の `catchUp`）は、担当待ちを見ずに営業日の終わりまで進める。未担当の案件の納期だけが減る
- 別の案件が動いている間に受注した案件は、担当が未定のまま納期が進む。タブに担当待ちの印がない
- 「ボトルネックが移動」の案内は「閉じる」以外で消えない。案件の納品・切り替え・ホームでも残る
- 初納品の瞬間に解放などの通知が十数件届き、上限（PC 3件・スマホ1件）で押し出されて見えない
- 担当が未定の工程が、工程ごとに別の問題カードになる

## やること
1. **締切を延ばす**：`balance.board.closeDays` を規模ごとに持ち、届いた営業日から数えて N 営業日目の `closeAt` に締め切る
2. **ボードを開いている間は時間を止める**：App の held にボードの開閉を加える
3. **見送りを履歴に残す**：`BidResult` を勝ち・負け・見送りの3つにする
4. **納期の選択肢に必ず差を付ける**：短縮は標準より1日以上短く、余裕は1日以上長くする。標準が1日なら短縮は選べない
5. **閉じている間の進行を止める**：プレイヤーの判断が要る状態（担当待ちの案件がある・見積を出していない引き合いが締切を迎える）になったらそこで止める
6. **受注した案件を放置させない**：担当が1つも決まっていない案件があれば時間を止める。タブに担当待ちの印を出す
7. **通知の整理**：
   - ボトルネックの案内は、案件の切り替え・納品・ホームで消す
   - 一度に届いた解放は「新しくできること」の1枚にまとめ、閉じるまで残す
   - 担当が未定の工程は、案件ごとに1枚の問題にまとめる

## テスト

- `tests/unit/bidding.test.ts`：納期の選択肢に必ず差があること、標準1日で短縮が選べないこと
