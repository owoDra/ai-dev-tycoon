# Phase 25: レスポンシブな画面構成

## 目的
スマホ（375px〜）と幅の狭い PC（768〜1024px）で、UI が重ならず 3D の世界が見える画面にする。

## 前提
Phase 24（案件ボードがシートになり、ホームができていること）

## 現状の原因（2026-10-28 調査）
- 上の帯・問題カード（`ProblemToasts`）・通知（`NoticeHost`）・用語カード（`TermCards`）・チュートリアル・納品カード（`DeliveryCards`）が、それぞれ `top-20` などの固定値で絶対配置されている。会社の帯（`CompanyStrip`）は折り返して高くなるため、問題カードに重なる
- `DeliveryCards` は帯の列の中で `absolute` になっており、帯の上に重なる
- スマホのドックに高さの予算がない（案件名・HUD・操作の列が積み重なって4〜5段になる）
- `ProjectTabs` の tablist が `min-w-0` で縮み、タブが溢れて「新しい引き合い」のボタンに覆われる
- シートの高さが「画面の高さ × 比率」で、ドックの高さを差し引いていない
- カメラ（`world/camera.ts` の `fitToLayout`）が上下の UI を考えずに画面全体へ合わせている
- 切り替えの幅は JS の 768px の1つだけ。`dvh`・セーフエリアに未対応

## やること
1. **領域による構成**：画面を「上の帯（会社・時計）」「お知らせの列（問題・通知・用語・納品）」「3D の世界」「シート」「ドック」の領域に分ける。各要素は自分の領域の中で流れに沿って並べ、領域どうしは重ならない。領域の寸法は `content/look/layout.ts` で定義する
2. **3つの形**：スマホ（〜599px）・狭い PC（600〜1023px）・広い PC（1024px〜）。形ごとに、ドックに出す項目・お知らせの最大件数・操作ボタンの出し方を `layout.ts` で定義する
3. **スマホのドック**：最大2段（案件名＋利益・納期 / 操作アイコン）。HUD の詳細はタップで開く。時計と一時停止は右上の小さなボタンにまとめる
4. **シートの高さ**：上の帯とドックを差し引いた高さまでに抑える
5. **カメラ**：3D の世界の領域（上の帯とドックを除いた範囲）に合わせて構図を決める
6. **ブラウザの都合**：`100dvh`、`env(safe-area-inset-*)`、`viewport-fit=cover`。画面の回転とブラウザのバーの出し入れに追従する
7. `ProjectTabs` の溢れを直し、横スクロールにする

## テスト
- `tests/unit/layout.test.ts`：375×667・390×844・768×1024・1024×768・1440×900 で、領域の矩形が重ならず、3D の世界の領域が一定の高さ以上残ること
- 見た目の確認は `npm run build:explore` のビルドを非公開の Artifact に出し、各幅のスクリーンショットを会話に示す
