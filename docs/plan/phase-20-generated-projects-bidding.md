# Phase 20: 案件の自動生成とコンペ

## 目的
固定7案件のキャンペーンを廃止する。会社の規模に応じた **多彩な案件が自動生成され、コンペに勝って受注する** 流れにする。

## 前提
Phase 19

## やること
1. **案件の生成（`core/projectGen.ts`、`content/projectTemplates.ts`）**
   - 今の7案件を「案件の型」（工程の依存関係・Task の種類と性質）に作り直す。業種（EC・SaaS・社内システム・メディア・決済…）と規模（S / M / L / XL）を掛け合わせて、Task の数・作業量・品質要求・納期を変える
   - 発注者の性格（価格重視・品質重視・納期重視）と予算の上限を持たせる
   - 案件の id から定義を決定論的に再生成できる形にする（例：`p~<seed>~<size>`）。`getProject` は生成した id も解決する。これで core の純粋性と、既存の `getProject` の呼び出しを保つ
   - 3D ワールド（`world/layout.ts`）が、生成した Task の数とグラフで破綻しないようにする
2. **案件ボード**：営業日ごとに引き合いが届く（数と規模の分布は会社の規模による。Phase 21 までは固定）。引き合いには応募の締切がある
3. **コンペ（`core/bidding.ts`）**
   - プレイヤーは見積を出す：見積人日（会社の見込み）× 平均売値 を基準に、値引き・上乗せと納期の提案を選ぶ
   - 勝率 = 見積額の安さ ＋ 提案力（評判・同業種の実績・納期の提案・AI 体制）を、seed から決まる競合数社と比べて決める。勝率は事前に表示する（Before / After 予測と同じ見せ方）
   - 締切に結果が出る（勝敗は state の RNG）。受注したら案件が始まり、**売上 = 見積額** になる
   - 納期を守れない・品質が低いと評判が下がり、次のコンペで不利になる
4. **キャンペーンの廃止**：`content/campaign.ts` と、固定の段階による進行・クリア判定を外す。チュートリアルは固定の案件のまま残し、終わったら案件ボードに移る。旧キャンペーンのセーブは読み込めない旨を出す（セーブ形式のバージョンを上げる）
5. 既存の固定案件を使ったバランステストは、固定 seed で生成した代表的な案件群で表し直す（判定条件は弱めない）

## テスト
- `tests/unit/projectGen.test.ts`：決定性、id からの再生成、依存関係が非巡回、規模で作業量が増える
- `tests/unit/bidding.test.ts`：安いほど・評判が高いほど勝率が上がる、勝率の表示と実際の判定が一致する
- `tests/balance/bidding.test.ts`：「常に最安値」も「常に高値」も最適にならない（利益 / 人日 の期待値で比べる）
