# Phase 34: 社員の掛け持ちと期限切れ

## 目的
人間の手は有限で、掛け持ちさせると効率が落ちる。期限に間に合わせるための配置を考える遊びにする。期限切れは大きな賭けの失敗として重く扱う。

## 前提
Phase 33

## 決定済みの方針（2026-10-28 ユーザー回答）
- 掛け持ち：1日の作業量を掛け持ち数で分け、さらに切り替えの手間で減らす（例：2件なら各40%、3件なら各25%）
- 案件の契約は2種類で、受注前に一覧でアイコンとラベルで示す
  - 期限厳守：期限が切れたらその場で打ち切り。入金なし（違約金なし）。報酬が高め
  - 炎上しても続行：期限が切れると炎上案件になり、作業は続く。納品すれば元の報酬が入る。延びた日数の人件費は自腹
- 期限切れの時点で評判と企業価値（上場後は時価総額）が下がる
- 会社側からも打ち切れる。入金なし、評判と企業価値は期限切れよりさらに下がる

## やること
1. 人間の待ち行列（1件ずつ直列）をやめ、担当中の工程すべてを並行に進める。速度に掛け持ちの係数を掛ける（係数は `balance.ts`）
2. 案件に契約の種類を持たせる（`content/` と案件の生成）。期限切れの処理と打ち切りの Command を足す
3. 企業価値に打ち切り・炎上の下げを反映する
4. 遅延損失（日ごとの減額）は、契約の仕組みに置き換える

## テスト
- `tests/unit/`：掛け持ちの係数、期限厳守の打ち切り、炎上の継続と納品時の入金、会社側の打ち切り
- `tests/balance/`：掛け持ちさせすぎると合計の作業量が減る。期限厳守の高額案件は、間に合えば得だが外すと大損になる
