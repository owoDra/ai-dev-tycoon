# Phase 17: バランス調整・性能・サイズ・a11y・仕上げ

## 目的
企画書65〜68章の MVP 要件と「狙う感覚」を満たして仕上げる。機能は追加せず、品質を上げることに集中する。

## 前提
Phase 15・16

## やること
1. **バランスの通し調整**
   - `tests/balance/` の全原則テストを、より多くの seed（例：50個）で実行するモード（`npm run balance:full`）を作り、通ることを確認する
   - `tools/balance-report.ts`：全案件 × 全戦略 Bot の主要指標を表として出力する。調整の判断材料にする
   - 支配戦略がないことを確認する：「1つの構成をコピーすれば全案件で最適」にならないよう、案件ごとに最適な構成が異なることをテストで確認する（`tests/balance/no-dominant.test.ts`）
2. **性能**
   - `?dev=perf` のオーバーレイ（FPS、draw call 数、パーティクル数、JS ヒープ）
   - 最も重い場面（複数案件の同時進行 ＋ Tier 4 演出）で 60fps を維持できるよう、上限値・LOD・テクスチャサイズを調整する
   - 起動の高速化：タイトル画面を先に描画し、3D とアセットのデコードは遅延・分割する。glb と WebP のデコードはアイドル時間に行う
   - バンドル分析（`rollup-plugin-visualizer` などを dev 依存で使う）で three の不要なモジュールを除き、サイズ予算を厳しくする（例：gzip ≤ 900KB）。`verify-dist.ts` の定数を更新する
3. **a11y**
   - コントラストのテストを全トークンの組み合わせに拡張する
   - 状態を色だけで伝えている箇所がないかを総点検する（アイコン ＋ ラベルを付ける）
   - キーボードだけでキャンペーンを最後まで遊べることを確認する。フォーカス順序とフォーカストラップ（モーダル）を見直す
   - `aria-live` で重要なイベント（事件の発生・完了・解放）を読み上げる
   - reduced-motion の総点検
4. **レスポンシブの総点検**：PC・タブレット・スマホの各幅でレイアウトを確認する。DOM テストで主要コンテナのクラスを検証する
5. **磨き込み**
   - 文言の総点検（短く・平易に。企画書63章）
   - 演出の Tier の総点検（全部が派手になっていないか。企画書43章）
   - 効果音のミックスバランス、BGM の音量の初期値
   - タイトル画面の第一印象（キービジュアル・アイドル演出・BGM のイントロ）
6. **README.md**（リポジトリ直下）：遊び方・ビルド方法・ディレクトリの概要だけを書く（詳細はコードを参照するよう案内する）
