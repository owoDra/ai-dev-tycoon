# Phase 18: 担当モードの再バランスと人日への移行

## 目的
Phase 17 後のプレイで見つかった問題を直す。
- 「AI → 自動テスト → 確認」が全案件・全 Task で最強になっている。AI の自動テスト工程が失敗を必ず見つけて直すため、人間レビューの上位互換になっている（`core/taskFlow.ts` の review かつ actor が ai の分岐）。
- 利益を「人時」で測るのは一般的でないので、**人日**（1人日 = 1営業日 = 480分）にする。
- エンジニアの単価を **売値（見積単価）** として持たせる。人日あたり最低5万・平均8万で、能力によって変わる。原価（給与）は売値とは別に持つ。

## 前提
Phase 17

## やること
1. **自動テストの検出率を有限にする**
   - Task の種類ごとに「自動テストのしやすさ」（`content/` のデータ。code・test は高く、planning・design・content は低い）を持たせる。AI の自動テスト工程は、この確率でしか失敗を見つけられない
   - 自動テストで見逃した失敗は、人間の最終確認で一定の確率（レビューより低い。balance に置く）で見つかり、手戻りになる。それでも見逃せば納品後の損害になる
   - 見込みの計算（`expectedHumanMinutes`・予測・振り返り）もシミュレーションと同じ流れにする
   - 狙い：作るものが検証しやすい Task は自動テスト、判断が中心の Task は人間レビュー、単純な Task は AI だけ、のように **Task ごとに最適なモードが分かれる**
2. **KPI を Profit / Person-Day にする**
   - スコア・HUD・結果画面・ランク・振り返り・結果コード・実務モードの「人時」を「人日」に置き換える（`balance.project.minutesPerBusinessDay` を換算に使う）
   - 結果コードは形式のバージョンを上げる（古いコードは「古い版」としてデコードを拒否する）
3. **売値と原価**
   - `HumanWorkerDef` の時給を、**売値（人日単価）** と **原価（人日あたりの給与）** に置き換える。原価は売値に対する比率（balance）から決める
   - 人件費 = 人間の稼働人日 × 原価。社員の画面に売値と原価を表示する
   - 今の社員5人に、能力に応じた売値（5万〜。平均8万前後）を付ける。売値が売上に効くのは Phase 20 のコンペから。この Phase では表示と原価の計算だけに使う

## テスト
- `tests/balance/modes.test.ts`（新規）：全案件のすべての Task について最適なモードを数え、どのモードも「全 Task の過半数で最適」にはならないこと。「AI → 自動テスト → 確認」と「AI → 人間レビュー」の両方が、どこかの Task で最適になること
- `tests/unit/formulas.test.ts`：自動テストの検出率・人間の最終確認での発見・見込みとシミュレーションの一致
- 既存のバランステストは、判定条件を緩めずに `balance.ts` とコンテンツの調整で通す
