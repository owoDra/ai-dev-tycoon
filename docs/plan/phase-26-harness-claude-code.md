# Phase 26: Harness を最新の Claude Code に寄せる（D6 を含む）

## 目的
Harness のパーツを、いまの Claude Code（Mod が使える版）で実際にできるカスタマイズと自動化に対応させる。初心者にも「どこに何を足すと何が変わるか」が見てわかる UI にし、実務モードから実際の設定一式を書き出せるようにする（Builder の画面には設定ファイルを出さない）。

## 前提
Phase 25

## 決定済みの方針（2026-10-28 ユーザー回答）
**パーツの刷新＋書き出し**（設定例の表示は Builder には出さない：2026-10-28 のデモへの回答）

## やること
1. **パーツの刷新**（`content/harness/`）。ゲーム内の効果は企画書の意図（高いモデルだけでは勝てない・Hook はお願いより確実・Subagent は2〜3が山・Tool は多いほど良いわけではない）を保つ

   | 種類 | パーツの例 | ゲーム内の効果 |
   |---|---|---|
   | Rules（`.claude/rules/*.md`） | 作業ルールをファイルごとに分け、対象のパスを触るときだけ読む | 指示の時間が減る。必要なときだけ読むので Noise が少ない |
   | CLAUDE.md / メモリ | 案件の概要・過去の学び | 指示の時間が減る。何でも書き込むと Noise（Rules へ分けるのが上手な手） |
   | Skill / スラッシュコマンド | Frontend Change・Report・/code-review | 決まった仕事の成功率が上がる |
   | Hook（タイミング別） | 道具を使う前のガード（PreToolUse）、編集後のフォーマット・Lint・テスト（PostToolUse）、完了前のチェック（Stop）、開始時の準備（SessionStart） | お願いより確実。タイミングで効く失敗が変わる |
   | MCP・コネクタ | Git・ブラウザ・DB・分析・チャット | 速さが上がる。付けすぎると誤選択 |
   | Subagent / Workflow / worktree | 調査・実装・QA の分担、並列化 | 並列化。worktree があれば衝突しない |
   | 権限モード | 毎回確認・auto mode・sandbox | 中断が減る ⇔ 事故のリスクが増える |
   | Mod | ステータスライン・横のパネル・トースト | 人間が見張る時間が減る |
   | Routine / 定期実行 | 夜間のテスト・定期レポート | 夜も AI が働く |
   | Eval | Unit Test・受け入れ基準・Security など | 見逃しを捕まえる |

   - 既存のパーツは新しい分類へ移す。セーブ形式を上げ、旧 id の読み替えを用意する
   - 解放の順番（`content/unlocks.ts`）を新しい分類に合わせる
2. **D6：Harness Builder の見た目**（D1〜D5 と同じ進め方。ユーザーの回答なしに採用しない）
   - 2026-10-28 のデモ（https://claude.ai/artifact/Gaecb4sU7NA1v5yhNsqVGp）への回答：「案A の作業の流れがわかる感じはいい。案B のシンプルさも捨てがたい。settings.json を出すのはいらない」
   - これを受けた案D（**採用**。2026-10-28 ユーザー回答「D はいい」）：作業の流れの道（受け取る → 計画 → 道具を使う → 書き換える → 確かめる → 渡す）に、各地点1つずつの丸いスロットを置く。Hook は道の上の「盾」。権限は「鍵」として道の下に置く。1つ目の地点（受け取る）には CLAUDE.md（毎回読む案件の地図）と Rules（作業ルール。関係するファイルを触るときだけ読む）の2つのスロットを並べる（ユーザーの指摘：作業ルールは rules を使うべきだが、CLAUDE.md がないのもおかしい）。ルールまで CLAUDE.md に詰めると Noise が増え、Rules に分けると減る。ミスがどこで止まるかを5つのカードで示す
   - どの案でも「おすすめ構成」（例：まず安全に／速さ重視／夜も回す）をワンタップで入れられるようにする
   - **「受け取る」の判定と UI**（2026-10-28 のデモ「ルールの仕分け」）：ルールをカード（大きさ・役に立つ仕事の種類）にし、「CLAUDE.md（毎回読む）」「Rules（関係する仕事のときだけ）」「渡さない」に仕分ける。判定は既存の Context（`core/context.ts`）に乗せ、新しい式を作らない
     - CLAUDE.md のカードはどの Task でも読む。その Task に役立たない分が Noise になる
     - Rules のカードは、役に立つ種類の Task のときだけ読む
     - 渡さないカードは、そのルールで防げるミスを防げない
     - CLAUDE.md には目安の長さを置き、超えると読み落とし（成功率の低下）が出る
     - 全部の仕事に必要なもの（案件の概要とコマンド）は CLAUDE.md が正解。「Rules に分けるほど良い」にはしない
3. **設定例は Builder に出さない**：Builder は効果と流れに集中する。実際の Claude Code の書き方は、実務モードの書き出し（下）でだけ扱う
4. **書き出し**：実務モードで組んだ Harness から、`.claude/` 一式（`settings.json`・`CLAUDE.md`・skills・agents・`.mcp.json`）をファイルごとにコピーできるようにする。外部への送信はしない
   - 書き出す内容が Claude Code の現行の形式に合っているかは、実装時に公式ドキュメントで確かめる
