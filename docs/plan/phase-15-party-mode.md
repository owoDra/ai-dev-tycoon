# Phase 15: 懇親会モード

## 目的
企画書28章。全員が同じ HTML・同じ Seed で開始し、「同じ Claude を使ったのに、なぜ結果が違ったのか」を振り返れるようにする。インターネットには接続しない。

## 前提
Phase 14

## やること
1. **モードの開始**：タイトル画面 →「懇親会モード」→ Seed 入力（例：`PARTY-2026-01`）とチーム名の入力。同じ Seed なら、案件・社員・AI予算・事件の発生が完全に同じになる（Phase 02 の決定性を利用する）。
2. **制限時間付きのセッション**：案件の構成と制限時間（例：25分）を Seed から決める。残り時間を HUD に大きく表示する。
3. **結果コード（`core/resultCode.ts`）**
   - チーム名・Seed・主要指標（Profit、Profit/Human h、Human Time、AI Cost、Quality）・ゲームのバージョンを、短い英数字のコードにエンコードする（Base32 ＋ チェックサム。読み上げやすいよう、紛らわしい文字を除く）
   - **リプレイの検証**：結果コードに Command 列のハッシュも含める。任意で Command 列そのもの（圧縮したもの）も出力でき、集計側で再シミュレーションして改ざんがないか検証できる
   - コピーボタンと、スマホで読み取れる QR コード（QR の生成は自前の小さな実装、または依存の少ないライブラリを使う）
4. **集計画面**（同じ HTML の「集計モード」）：複数チームの結果コードを貼り付けると、企画書28章の比較表を作る
   - 列：Team / Profit / Profit/Human h / Human Time / AI Cost / Quality。各列で並べ替えでき、1位を強調する
   - 発表用の演出：順位を下位から1チームずつめくる表彰モード（Tier 4 ＋ ドラムロールの効果音）
   - 「なぜ違ったか」のヒント：各チームの構成の特徴（Eval 導入の有無、Premium の数など）を、リプレイから抽出して1行で表示する
5. 集計の状態は localStorage に保存する（失敗しても動くようにする）

## テスト
- `tests/unit/resultCode.test.ts`：エンコードしてデコードすると元に戻る、1文字でも変えるとチェックサムで検出できる、バージョン違いを検出できる
- `tests/unit/party-determinism.test.ts`：同じ Seed・同じ Command 列なら結果コードが一致する、Seed が違えば案件構成が変わる
- `tests/view/leaderboard.test.ts`：並べ替えと順位付け（同点の扱い）

## 完了条件
- [ ] Seed を入力して開始し、終了時に結果コードと QR コードが表示される
- [ ] 集計画面で複数のコードを貼り付けると比較表と表彰演出が出る
- [ ] 上記テストが通る。`npm run check` が exit 0
- [ ] 外部通信を一切行わない（`verify:dist` で担保する）
