# Phase 16: Workflow Library・実務モード

## 目的
企画書24〜25章。良い改善を「○○さんはClaudeがうまい」で終わらせず、再利用可能な組織の資産に変える。また、ゲームと同じ考え方で実際の仕事の改善効果を試算できるようにする。

## 前提
Phase 14（Phase 15 とは独立しているので、順序は入れ替えてもよい）

## やること
1. **Workflow Library**
   - 保存：結果画面または Harness Builder から、AI Worker の構成（Context・Skill・Tool・Subagent・Hook・Eval・Permission）と担当モードの組を、名前を付けて保存する
   - 再利用：次の案件で、Task に Workflow を「適用」すると一括で構成される。適用時に Before → After の予測を表示する
   - 実績の表示：その Workflow を使った回数・削減した人間時間の累計（会社の資産らしく見せる）
   - **共有コード**：Workflow を文字列コードとして書き出し、読み込めるようにする（懇親会で他チームの構成を試せる）。読み込み時はスキーマを検証し、未解放の部品が含まれていれば警告する
   - 3D 演出：保存すると、オフィスの「ライブラリ棚」にバインダーのモデルが1冊増える（Tier 3）
   - 企画書25章の例である PR Review などのプリセットを、いくつか同梱する
2. **実務モード（`content/practice/` と `ui/practice/`）**
   - 実際の業務を入力するフォーム：業務名・頻度（毎日 / 毎週 / 毎月）・現在の人間時間・工程（最大8つ）・各工程の AI 適性（選択式）
   - 改善の設計：各工程に担当モードと Harness 部品を割り当てる。UI はゲームの Harness Builder と共通にする
   - 試算（`core/practice.ts`。純粋関数）：改善後の人間時間、年間の削減時間、AI の追加コスト、ROI、人時あたりの利益
   - 例として、企画書24章の「週次アクセス解析（120分 → 15分）」をテンプレートとして同梱する
   - 結果は数字を主役にした「8.4h → 1.7h / -80%」の見せ方にする。テキストやMarkdownとしてコピーできるようにする
   - 入力内容は localStorage に保存する（失敗しても動くようにする）

## テスト
- `tests/unit/workflow-library.test.ts`：保存して適用すると構成が一致する、共有コードの往復変換、不正なコードを拒否する
- `tests/unit/practice.test.ts`：週次アクセス解析のテンプレートで、人間時間が 120分 → 15分前後になり、年間の削減時間と ROI が手計算の期待値と一致する
- `tests/content/presets.test.ts`：同梱プリセットの参照先が存在する

## 完了条件
- [ ] Workflow を保存して別の案件に適用でき、共有コードで受け渡しできる
- [ ] 実務モードでテンプレートを開き、改善を設計して ROI を確認し、結果をコピーできる
- [ ] 上記テストが通る。`npm run check` が exit 0
